# CLAUDE.md for `<AppName>-ios`

Purpose. This file is copied verbatim to the root of the iOS repository as `CLAUDE.md` in Phase 0 and is loaded into
every Claude Code session there. It carries the standing rules the plan's other documents assume: what is where, how
the two products are built and tested, what may not be imported, how secrets and copy are handled, and what to do
when the plan and reality disagree. Each rule is one imperative sentence followed by its reason. Names are the ADR's
(10-decision-record.md §2) verbatim; a rule that another document owns cites it rather than restating it.

Read with: 04-ios-app.md (the repository map, module signatures and coding rules these rules enforce),
03-server-api.md (every shape, header and the routes never called), 07-build-phases.md (the phase gates and the
pull-request form), 09-security.md (token, transport and logging rules in full), 02-architecture.md (§4 the
Keychain and `UserDefaults` tables, §5 the concurrency model), 10-decision-record.md (binding), and the current
`docs/build/phase-N.md`.

## 1. Repository facts

- Treat `project.yml` as the only project description. The `.xcodeproj` is generated by XcodeGen, gitignored and
  regenerated by CI (constraints brief fact 13; 04-ios-app.md §1).
- Never edit, commit or hand-repair a `.pbxproj`. A hand edit is lost on the next `xcodegen generate` and cannot be
  reviewed.
- Keep the two products where 04-ios-app.md §1 puts them: `PlexGetKit/` (Swift package, Linux-buildable) and `App/`
  (the SwiftUI target). Every later phase names files by that map.
- Build `PlexGetKit` from `Foundation` only, with `FoundationNetworking` behind `#if canImport(FoundationNetworking)`.
  It must build and test on Linux, where the builder runs (ADR §2).
- Never import `Security`, `StoreKit`, `UserNotifications`, `UIKit` or `CryptoKit` under `PlexGetKit/`. Platform
  behaviour reaches the Kit only through the four protocols `SecretStore`, `Entitlements`, `Transport` and
  `Notifier`, implemented in `App/` (ADR §2; 04-ios-app.md §2.1).
- Keep every product, bundle, topic and domain constant in `App/AppIdentity.swift` and nowhere else. Renaming the
  app is one edit there plus `project.yml` (ADR §4 "App Store name"; 04-ios-app.md §3.1).
- Treat `PlexGetKit/Tests/Fixtures/` as vendored, read-only data refreshed only by `scripts/sync-fixtures.sh
  <path-to-server-repo>`, with the server commit in `Tests/Fixtures/VERSION`. Fixtures are the contract with the
  server and are never edited by hand (03-server-api.md §6.3).
- Keep the phase prompts at `docs/build/phase-N.md` and the deviation log at `docs/build/deviations.md`. Later Mac
  sessions find their instructions there (00-README.md §3).

## 2. Toolchain and the exact commands

- Use Swift 6 language mode, `swift-tools-version: 6.0`, `SWIFT_STRICT_CONCURRENCY = complete` and
  `-warnings-as-errors` in both `Package.swift` and `project.yml`. Strict concurrency turns data races into compile
  errors (constraints brief fact 11); a warning fails CI (04-ios-app.md §10.1).
- Target iOS 17.0 and nothing lower. `@Observable`, StoreKit 2 and `NavigationStack` need it (constraints brief
  fact 11).
- Use Xcode 16.x on macOS 15 (unverified: the point release on the `macos-15` runner; Phase 0 records and pins
  it in `.github/workflows/app.yml`, 07-build-phases.md §2, §4.3). An older Xcode has no Swift 6 and no swift-testing.
- On Linux, run the Kit gate exactly as: `cd PlexGetKit && swift build -Xswiftc -warnings-as-errors && swift test`
  (pass: "Test run with N tests passed"). This is the only gate the builder can run without a Mac.
- On a Mac, run the app gate exactly as: `xcodegen generate` then `xcodebuild test -scheme App -destination
  'platform=iOS Simulator,name=iPhone 16' -derivedDataPath build CODE_SIGNING_ALLOWED=NO` (pass: "** TEST
  SUCCEEDED **"). The simulator destination needs no signing (ADR §5 item 16).
- Run `scripts/lint.sh && scripts/banned-words.sh` before every commit (pass: no output, exit 0). They are the
  mechanical form of §4 and §6 below and run in both CI workflows (07-build-phases.md §4.2).
- In a Linux session, list every Mac command under `## Not run here` in the pull request with the reason. The human
  runs it; a phase does not pass until it has (07-build-phases.md §1.1 item 3).

## 3. Dependencies

- Add no third-party Swift package, binary, script or SDK. Keychain, networking, JSON, QR scanning (VisionKit),
  images and StoreKit are Apple frameworks (constraints brief fact 12).
- Keep `dependencies` absent from `Package.swift` and `packages` in `project.yml` limited to the local `PlexGetKit`.
  `scripts/lint.sh` fails on anything else (07-build-phases.md §4.2).
- If a dependency seems necessary, stop: write the six-line deviation note (§8) naming what Apple's frameworks
  cannot do, commit it and end the session. The owner decides; the builder never adds one on its own.

## 4. Code rules

- Never force-unwrap outside a test target. A `nil` is a decoding or state bug to surface, not to crash on
  (04-ios-app.md §10.2).
- Never write `try!` or `as!`. Errors go through the mapper and the store; a crash hides the shape that broke.
- Confine `preconditionFailure` and `fatalError` to the URL literals in `App/AppIdentity.swift`. That is the one
  place a literal URL exists (04-ios-app.md §3.1; `scripts/lint.sh`).
- Never call `print`. Use `os.Logger` in `App/` with `privacy: .private` on every interpolation that is not a route
  name; the Kit has no `os` import and logs nothing (09-security.md §3).
- Never interpolate a token, pin, handle, secret, JWS or notification body into a log, even privately. Redaction is a
  courtesy, not a boundary.
- Build a `URLRequest` only in `PlexGetKit/Sources/PlexGetKit/ServerAPI/Endpoints.swift`. One builder per route in
  03-server-api.md §3-§4, per plex.tv call and per relay call; the header set of 03 §1.2 is applied there once
  (ADR §2).
- Use `URLSession` only in `App/Session/URLSessionTransport.swift`, the app target's `Transport`. The Kit talks
  to the network through `Transport` alone (02-architecture.md §5 item 2; 07-build-phases.md §4.2). Note:
  00-README.md §4 says "inside `ServerClient` and `PlexTV`"; the ADR's protocol boundary puts the session in the app
  target, and 04, 07 and 09 agree, so follow this rule.
- Never write a string literal for an endpoint path outside `Endpoints.swift`. `scripts/lint.sh` and
  `scripts/banned-words.sh` grep for the paths of 03-server-api.md §8, so a stray literal fails CI.
- Never write `@unchecked Sendable`, `nonisolated(unsafe)`, `DispatchQueue`, `NSLock`, a semaphore or `Thread`.
  Strict concurrency is the point; an escape hatch needs a comment stating why the compiler is wrong, and no such
  case is expected in v1 (02-architecture.md §5 item 3; 04-ios-app.md §10.1).
- Never write `Task.detached` except inside `Background.run(task:)`, whose expiration handler cancels it. Detached
  tasks lose the actor and cancellation context (02-architecture.md §5 items 3 and 7).
- Make every store `@MainActor @Observable final class <Feature>Store`, one per feature folder, holding one
  in-flight `Task` per operation that is cancelled before the next and checks `Task.checkCancellation()` after each
  await. Views read stores; stores call `SessionStore` or the Kit; a view never calls the client (04-ios-app.md §10.1).
- Make every `Models` type a `Sendable` `struct` or `enum` with `Codable` and no reference semantics. Nothing crosses
  an actor boundary that is not `Sendable` (02-architecture.md §5 item 4).
- Decode with `Models.decoder` (`keyDecodingStrategy = .convertFromSnakeCase`), ignore unknown keys, make every field
  03-server-api.md lists as required non-optional, and give `Film` no `missingFiles` property at all. Leniency is
  for unknown keys only; a missing required field must fail (04-ios-app.md §2.3; ADR §6 item 8).
- Parse every timestamp with `SQLiteDate` (`YYYY-MM-DD HH:MM:SS` UTC, ISO 8601 `Z`, or a Unix integer) and format in
  the app with the current locale. The server mixes three formats (owner-api.md §4.10).
- Never open a URL taken from a push payload, an event or a server response; route only by `ref` matching
  `^(wanted|message|note):[0-9]+$`. `openURL` exists only in `Report` and `Paywall` (09-security.md §2.6).
- Never answer a server-trust challenge, add `NSAllowsArbitraryLoads` or `NSExceptionDomains`. ATS is exactly
  `{ NSAllowsLocalNetworking: true }` and certificate validation is the system default (09-security.md §4).
- Never send plain `http://` to a host that `AddressClass.isPrivate(host:)` rejects, and prefer `https://` when both
  answer. Remote traffic is HTTPS by rule (constraints brief fact 10).
- Never send `Cookie` or an `X-Plex-*` header to a PlexGet server; send `Accept: application/json` exactly. The
  guard redirects HTML-accepting requests and the cookie is the web page's credential (03-server-api.md §1.2).

## 5. Secrets

- Store every secret only in the Keychain through `SecretStore`, under the account names of 02-architecture.md §4.1,
  with `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`, service `AppIdentity.keychainService`, no
  `kSecAttrSynchronizable` and no access group (constraints brief fact 15).
- Never write a token, pin, handle, secret, JWS or server key to `UserDefaults`, a file, a cache, the pasteboard,
  `NSUserActivity` or a log. 02-architecture.md §4.2 lists every permitted `UserDefaults` key; the changes cursor and
  URL sets are the only per-server state outside the Keychain.
- Never log a token, even redacted, and never include one in a `description` or `debugDescription`. `RedactionTests`
  asserts it (09-security.md §11).
- Never commit a fixture, screenshot, log or review note containing a real token, key, handle or owner address. The
  server's writer normalises `token` to `FIXTURE-TOKEN-…` and `server_key`/`relay_handle` to `FIXTURE-KEY`
  (03-server-api.md §6.2); a fixture with anything else in those keys is a stop.
- Never commit a `.p8`, a `.env`, a provisioning profile or a signing certificate. The APNs key lives only in the
  relay's secret store (ADR §2).
- Send the plex.tv account token only to `https://plex.tv/api/v2`; the exchange body carries `pin` and `device`, and
  `plex_token` only in the gate-1 fallback to a typed `https://` address (09-security.md §5).

## 6. UI copy

- Never write, in any case, in `App/`, `PlexGetKit/`, the fixtures, screenshots or store metadata: `download`,
  `torrent`, `usenet`, `nzb`, `indexer`, `sonarr`, `radarr`, `tracker`, `seed`, `magnet`, `release group`. App Review
  has rejected apps for less (constraints brief fact 8; 04-ios-app.md §10.3; ADR §6 item 10).
- Never put "Plex" in the app name, icon or `CFBundleDisplayName`; "for Plex" is the owner's subtitle decision only
  (constraints brief fact 9).
- Call the wanted list "the list", "the wish list" or "what you've asked for", and arrival "it's here" or "on the
  shelf". Those are the app's words for a wish list (04-ios-app.md §10.3).
- Never mention the web dashboard, a website purchase or a code. The Console unlocks by StoreKit only (constraints
  brief fact 6).
- Write every user-facing string in British English (`en-GB`) in `Localizable.xcstrings` with a translator comment;
  never assemble a sentence by concatenation. It is the only catalogue and the only language in v1 (04-ios-app.md §9).
- Show server-provided text (`app_name`, persona text, `interpretation`, error `message` and `hint`, notification
  titles and bodies, playlist names, announcements) verbatim and never localise it (04-ios-app.md §9).
- Render exactly the persona keys `name`, `greeting`, `brush_offs`, `images`, `brush_off_moods`, `smart_mode`;
  never model, request or store `voice` or `examples`. They are server-side instructions (ADR §4 "Persona";
  persona-themes-limits.md §1.3, §8 item 1).
- Show "Notifications may arrive late" only in the polling state, never as general copy (ADR §1; design-A §5.3).
- Use the in-app name from the server's `app_name`, never `AppIdentity.displayName`, in headers and sentences.
  A server called "Plex Requests" shows that name whatever the store listing says (design-A §9).

## 7. Testing

- Run `swift test` and `xcodebuild test` on every pull request; label the pull request `mac-ci` so `app.yml` runs on
  it. The Linux workflow runs on every push; the macOS one only on `main`, the label or dispatch (07-build-phases.md §4).
- Keep `FixturesTests` decoding every file under `Tests/Fixtures/` with its catalogued type and asserting that every
  catalogue entry has a file. It is the contract test between the two languages (03-server-api.md §6.3; ADR §4 "Fixtures").
- Never skip, disable, comment out, `XCTSkip` or `.disabled()` a test to make a gate pass. A failing test is a
  deviation note, not an obstacle.
- Never open a network connection in a test; inject `FakeTransport`, `MemorySecretStore`, `FixedEntitlements` and
  `RecordingNotifier` from `Tests/PlexGetKitTests/Fakes/` (04-ios-app.md §2.1).
- Launch every UI test with `--demo --uitest` and use only identifiers from `Shared/Identifiers.swift`. UI tests
  touch no network, Keychain, StoreKit or notifications (04-ios-app.md §11).
- Add the security tests 09-security.md §11 names for the phase, by name. The phase gate lists them.

## 8. Process

- Work one phase per session, starting by reading `docs/build/phase-N.md` in full and the documents it names under
  Inputs. The prompt carries the context; this file carries the rules (00-README.md §3).
- Never start Phase N+1 until Phase N's pull request is merged with every gate command's output pasted and its
  human step recorded. The only permitted overlap is Phase 8 with Phases 4 to 7 (07-build-phases.md §1.1 item 4).
- Branch `phase-N-<slug>` from `main` and title the pull request `Phase N: <name>`, with the headings of
  07-build-phases.md §1.2 in order: Goal, Changed, Gate output, Not run here, Human steps, Deviations, Forbidden.
- Paste every gate command and its complete output verbatim under `## Gate output`; never write "passes" or
  "verified" without the output. A claim without output is treated as a failed gate.
- Keep each commit about one thing, with an imperative first line under 72 characters naming the phase
  (`Phase 3: add SQLiteDate decoder`) and a body that says why in plain British prose; never "we" (`CONTRIBUTING.md:81`
  and its house style). A rename buried in a behaviour change survives review.
- When reality contradicts the plan (a shape the Kit cannot decode, an Apple or Plex behaviour that differs, a gate
  that cannot pass for a reason the plan did not foresee), append one six-line entry to `docs/build/deviations.md`
  in this order: date; phase number and name; document and section that made the claim; what was observed, with
  the command or file that shows it; the settling source, marked (verified: how) or (unverified); the smallest
  change to the plan that resolves it. Commit it on the phase branch and stop (00-README.md §4).
- Never work around a contradiction, never fake data outside `DemoServerClient`, and never invent an endpoint,
  field, column or file name. Missing things are `GAP:` lines in 03, 04, 05 or 06 and are added server-side with
  tests first (07-build-phases.md §1.1 item 6).
- Never do a human step (Developer Program, App Store Connect, capabilities, the APNs key, products, TestFlight,
  the App Store name) or claim it done. Record it as `pending` under `## Human steps` (00-README.md §6).

## 9. When the server API and 03-server-api.md disagree

- Stop coding Swift the moment a real response, a fixture or a status code differs from 03-server-api.md. The
  document is the contract, and a lenient guess in Swift hides drift until a household hits it (ADR §6 item 8).
- Decide which side is wrong by reading the cited server code (`file:line` in 03) and the fixture; if the server
  is wrong, fix it in the server repository with a pytest test under `tests/`, re-run `pytest -q` so the fixture
  is re-recorded, and commit the fixture; if the document is wrong, change the document in the same pull request.
- Then run `scripts/sync-fixtures.sh <path-to-server-repo>`, commit the new `VERSION`, and only then resume the
  Kit change. The Kit follows the fixture, never the other way round.
- If the right fix is not obvious, or would change a shape another screen depends on, write the deviation note (§8)
  and stop. The owner decides between the two shapes; the builder does not.
- Never call a route in 03-server-api.md §8 to get around a missing field. Those routes are excluded for App Review
  and privacy reasons, not by oversight (constraints brief fact 8; 09-security.md §8).
