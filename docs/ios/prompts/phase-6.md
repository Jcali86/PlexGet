## Goal

Build `push-relay` in `<AppName>-relay`: every endpoint of `05-push-relay.md` §4 over the four tables of §3, the APNs sending path of §7 through an `APNsClient` protocol, the entitlement rules of §5 through Apple's App Store Server Library, the fixed-window quotas of §6, JSON-line logging that never carries a body, and a pytest suite against a fake APNs endpoint and a fake verifier with every §12 case present by name; deploy it to `push.<developer-domain>`. Then give the app `PushBridge` (APNs token → `POST /v1/devices` → `POST /api/v1/push/devices`), `Background` polling of `GET /api/v1/changes` with local notifications through `UserNotificationsNotifier`, deep links by `ref`, the in-context permission prompt after the first sign-in, Bell's push state and "Send a test", and Settings' deletion of a member's relay handle; prove a push from a Phase 2 server through the deployed relay reaches a TestFlight build and a forced `BGAppRefreshTask` posts a local notification.

## Constraints

- Before `relay/entitlements.py` or `relay/apns.py` is written, read the App Store Server Library's README (PyPI name, module, verifier class, constructor, root certificates) and Apple's "Sending notification requests to APNs" and "Establishing a token-based connection to APNs" (header names, `410` and `400 BadDeviceToken` semantics, the two hosts), and "Supporting associated domains" for the AASA shape; record each as (verified: <url>, <date>) in `docs/verified.md`. A disagreement with 05 §4.8, §5 or §7 is corrected in 05 in the same pull request; one that changes an endpoint's answer to the server or the app is a deviation note and a stop (`10-decision-record.md` §6 items 4 and 5).
- The relay never accepts, stores, forwards or logs a Plex token, a session token, a server address, a username, an email or a plex.tv account id; `POST /v1/push` rejects any field outside `handle`, `event`, `title`, `body`, `collapse_id`, `data.ref`, `data.srv` with `400 bad_request`; a `title` or `body` is never written to the database, a log line, a metric or an exception message.
- `handle` and `device_secret` are two distinct random values; `device_secret` and `server_key` are stored only as `sha256` hex and returned once; quota subjects for IPs are `sha256(ip + RELAY_QUOTA_SALT)`; counters live in SQLite and are incremented only on `sent`, `unregistered` and `apns_unavailable`.
- Dependencies are exactly Flask, `waitress`, `httpx[http2]`, `PyJWT[crypto]`, Apple's App Store Server Library and `sqlite3`, pinned in `requirements.txt`; `pytest` 8.x in `requirements-dev.txt`; nothing else. One process, eight threads, one container.
- In the app: `URLSession` only in `App/Session/URLSessionTransport.swift`; every `URLRequest` including the relay calls built in `PlexGetKit/Sources/PlexGetKit/ServerAPI/Endpoints.swift`; the relay handle and secret only in the Keychain under `relay.handle` and `relay.device-secret`; the changes cursor (`changes.<machine_id>.cursor`) and the `push.seen` ring are the only push state in `UserDefaults`; `Task.detached` only inside `Background.run(task:)` with the expiration handler cancelling it.
- Never open a URL taken from a push payload or an event; route only by `ref` matching `^(wanted|message|note):[0-9]+$` through `ChangeRouting` and `Router.open`.
- Forbidden in this phase (07 §5 Phase 6): logging or storing a push body or title in the relay; a Plex token, session token or server address in any relay request, table or log; a Notification Service Extension; App Attest; a `.p8` file or its contents in either repository; `StoreKit`; the `POST /v1/server-keys` client in the app (Phase 7); a second relay worker.

## Do not

- Do not write `relay/entitlements.py` or `relay/apns.py` from memory of Apple's names; write `docs/verified.md` first, and if a page cannot be read, stop with the deviation note.
- Do not hand-roll JWS chain verification, notification decoding or certificate checks; `SignedDataVerifier` is the only verifier.
- Do not log, store, or put in an exception message a notification `title` or `body`, a full handle, a device secret, a server key, a JWS or a raw IP address.
- Do not accept, forward or store a Plex token, a session token, a PlexGet server URL, a username or an email on any relay route; `data.srv` is the public machine identifier and nothing else.
- Do not return `device_secret` from any route other than `POST /v1/devices`, and do not make it equal to, or derivable from, the handle.
- Do not add a route, table, column, field or dependency that `05-push-relay.md` does not name; `GET /v1/server-keys/<id>` stays unbuilt.
- Do not open a real socket in any relay test, and do not skip, `xfail` or delete a test to pass the gate; a failing test is a deviation note.
- Do not add a Notification Service Extension, App Attest, a `.p8` file or its contents, `StoreKit` code, or the `POST /v1/server-keys` client to the app in this phase.
- Do not open a URL from a push payload or an event, and do not store anything but the changes cursor and the seen ring for push state in `UserDefaults`.
- Do not claim the TestFlight push or the forced background refresh as done; both are the owner's device steps and the phase does not pass without their pasted evidence.
