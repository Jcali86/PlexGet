## Goal

Complete every household screen so that a member can do everything the web page does today except install it to the home screen: Detail (the long-press peek as a sheet), Playlists (list, items, remove, auto-build, and the owner's "Make someone a playlist"), WantedList (Waiting / Arrived / Set aside), Bell (announcements, the unread dot, the notification state without push yet), Looks (four built-ins plus owner-made looks, `user.skin` honoured unless the person chose their own), Report (the owner path through `POST /request/message` and the developer path through Mail), Help with the tour, and Settings (own sessions, sign out, sign out everywhere, the Home-network toggle). Every screen works against `DemoServerClient` and against a merged Phase 2 server, the Phase 5 UI tests pass, and a recorded walk of the 21 member flows proves each one.

## Constraints

- Use only endpoints and fields in `03-server-api.md` §3 and §4; build every `URLRequest` in `PlexGetKit/Sources/PlexGetKit/ServerAPI/Endpoints.swift` (Phase 3 built the builders; add none). A missing field is a stop, not a guess.
- A response shape that differs from `03-server-api.md` is fixed by a server pytest test and a document change in `<server-repo>`, then `scripts/sync-fixtures.sh <server-repo>`; never by a lenient guess in Swift (`10-decision-record.md` §6 item 8; `CLAUDE.md` §9).
- Every user-facing string lives in `App/Resources/Localizable.xcstrings` in `en-GB` with a translator comment; server-provided text (`app_name`, persona text, `interpretation`, error `message` and `hint`, playlist names, announcements) is shown verbatim and never localised.
- Render exactly the persona keys `name`, `greeting`, `brush_offs`, `images`, `brush_off_moods`, `smart_mode`; nothing in this phase models, requests or stores `voice` or `examples`.
- Every store is `@MainActor @Observable final class <Feature>Store`, one per feature folder, one in-flight `Task` per operation cancelled before the next, `Task.checkCancellation()` after each await; a view never calls the client.
- Tokens only in the Keychain through `SecretStore`; `UserDefaults` holds only the keys of `02-architecture.md` §4.2 and the additions `04-ios-app.md` §4 declares, all in `App/Settings/DefaultsKeys.swift`.
- `openURL` exists only in `Report`, `Bell`, `Settings`, `Welcome`, `Pairing` and (Phase 7) `Paywall`, and its argument is only `AppIdentity.privacyPolicyURL`, `AppIdentity.termsURL`, `AppIdentity.appStoreURL`, `UIApplication.openSettingsURLString` or a `mailto:` to `AppIdentity.supportEmail`, never a value from a server response, an event or a push (09 §2.6, §11); no view names a `Color` literal, every colour comes from the `\.look` environment.
- Show "Notifications may arrive late" only when `server.<machine_id>.delivery` is `polling`, never as general copy.
- Forbidden in this phase (07 §5 Phase 5): a new endpoint or field; a deviation from a `03-server-api.md` shape without a server pull request first; Console screens; `StoreKit`; push and background code (`PushBridge`, `Background`, `import UserNotifications`); a banned word (`CLAUDE.md` §6); a `.storekit` file.

## Steps

Calls `Endpoints` for `GET /request/detail?key=` (03 §4.10) and `POST /request/playlist` (03 §4.8) for "Add to my list"; backdrop from `art` at 900x500 through `client.artworkURL(path:width:height:)`; the season list for shows; `.notFound` closes the sheet with "Not on the shelf" (02 §6.4). 4. Playlists: `App/Playlists/PlaylistsStore.swift`, `PlaylistsView.swift`, `PlaylistItemsView.swift`, `AutoBuildView.swift`, `GiftPlaylistView.swift` (owner only, reached from Home's door and the Playlists tab). ## Do not

- Do not add a builder to `Endpoints.swift`, a query parameter or a body field that `03-server-api.md` §3 and §4 do not list; a screen that seems to need one is a deviation note.
- Do not make a field optional in a `Models` type, add a fallback default or catch a `DecodingError` to get a screen past a response the Kit cannot decode; fix the server with a pytest test and re-sync the fixtures.
- Do not write any Console screen, `ConsoleTab`, `ConsoleGate` content, `Store`, `Products.storekit` or any `import StoreKit`; the Console tab is Phase 7.
- Do not write `PushBridge`, `Background`, `UserNotificationsNotifier`, a `UIBackgroundModes` entry or any `import UserNotifications`; Phase 6 owns them, and `PendingNotifier` is the only notifier this phase adds.
- Do not show "Notifications may arrive late" anywhere except Bell and Settings when the last `push.delivery` seen was `polling`.
- Do not write a token, session, handle or the plex.tv account token to `UserDefaults`, a cache file or an `os.Logger` line, and do not add a `UserDefaults` key outside `DefaultsKeys.swift`.
- Do not send the developer report through the server, through any endpoint, or with anything beyond the app version, iOS version and server `build` in the body.
- Do not call `/wanted/export`, `/export*`, `/sonarr/*`, `/radarr/*`, `/push/test`, `/auth/*` or any other route in `03-server-api.md` §8, and do not write a string containing a word from `CLAUDE.md` §6.
- Do not skip, disable, `XCTSkip` or comment out a UI test, and do not edit a file under `PlexGetKit/Tests/Fixtures/` by hand.
- Do not mark a walk row as done against the real server unless the action was performed against a running Phase 2 server and the observed result is written in the row.
